# Terminologia

| Termo | Uso nesta plataforma |
| --- | --- |
| BCM | continuidade do negócio como um todo |
| ITSM | gestão de serviços de TI; o “M” significa *Management* |
| ITSCM | continuidade dos serviços de TI que suportam o negócio |
| Disaster Recovery | recuperação técnica de infraestrutura, dados, aplicações e serviços |
| Control plane | camada externa que descobre, correlaciona, decide e orquestra |
| Federated Source of Truth | fontes autoritativas por domínio, reconciliadas em uma visão comum |
| Desired state | estado pretendido em Git, Terraform ou GitOps |
| Actual state | realidade observada por backend e APIs |
| Recovery readiness | capacidade demonstrável de recuperar agora |
| RTO | tempo máximo tolerável para restabelecer o serviço |
| RPO | perda máxima de dados expressa como distância temporal |
| Recovery tier | classe que agrupa criticidade, objetivos e estratégia |
| Recovery point | backup, snapshot ou posição de log elegível para restore |
| Evidence | prova estruturada e íntegra de input, decisão, execução e resultado |
| CRD | extensão declarativa da Kubernetes API com schema próprio |
| Operator | controller que reconcilia Custom Resources por control loops |
| Adapter | implementação de um contrato do control plane para um sistema externo |
| Failure domain | conjunto de componentes que pode falhar pela mesma causa |
